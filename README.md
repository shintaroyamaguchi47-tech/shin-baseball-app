# ⚾ 配球スコア・分析アプリ Pro

野球の配球記録・分析アプリ。投球コース(7×7)・球種・結果を記録し、ヒートマップ、スプレーチャート、セイバーメトリクス指標(CSW%、チェイス%など)によるリアルタイム分析、PDF試合レポート出力ができます。

## 開発

```bash
npm install      # 依存パッケージのインストール
npm run dev      # 開発サーバー起動 (http://localhost:5173)
npm test         # テスト実行
npm run build    # 本番ビルド (dist/ に出力)
npm run preview  # ビルド結果のプレビュー
```

## 構成

- **Vite + React 18 + Tailwind CSS v3** — すべてローカルにバンドルされ、オフラインで動作します(CDN依存なし)
- `src/App.jsx` — アプリ本体(画面・状態管理)
- `src/analystInsights.js` — アナリスト指標の算出ロジック
- `src/pdfReport.js` — PDF(印刷用HTML)レポート生成
- `src/scorebookReport.js` — スコアブックPDF(印刷用HTML)生成。紙面の組版まで自前で行う(下記)
- `src/components/` — SprayChart(スプレーチャート)、AnalystReport(アナリスト分析画面)
- データは localStorage(`baseball_*_v2` キー)に自動保存されます

## フェーズ1: 累計分析基盤

ヘッダーの「分析ハブ」から、保存済みの複数試合を横断して利用できます。

- 自チーム分析: 期間・試合種別・相手・選手で絞り込み、得失点、イニング別得失点、OBP、SLG、OPS、K%、BB%、被打率、WHIP目安、初球ストライク率、失策を表示
- 選手カルテ: 個人の打撃・投球累計、試合別記録、育成メモを端末内に保存
- 対戦相手分析: チームと選手を自チームとは分離し、同一相手との複数試合を累計したスカウティング表示
- 正規化ビュー: `teams`, `players`, `games`, `gameRosters`, `plateAppearances`, `pitches`, `battingEvents`, `pitchingEvents`, `fieldingEvents`, `baserunningEvents` を既存の試合スナップショットから再構築

### データ移行方針

既存の `baseball_*_v2` データは変更・削除しません。分析画面を開くたびに保存済み試合の生データから正規化ビューと累計値を再計算します。そのため、従来版からの手動移行は不要で、記録を修正した場合も次の表示で集計に反映されます。選手メモのみ新しい `baseball_playerNotes_v3` に保存されます。

「自チーム」の判定は分析対象のチーム選択で行えます。将来サーバーDBへ移す場合は `src/analyticsData.js` の正規化結果をそのままテーブル移行の入力として利用できます。

## フェーズ2: 育成・戦術分析

オーダー設定で「試合種別」と「自チーム」を設定すると、その後の保存試合に引き継がれます。

- 投球回・防御率目安・WHIP・被打率・初球ストライク率をアウト記録から再計算
- 盗塁成功率、失策、先制時勝率、先制された場合の勝率、終盤得失点を表示
- 選手カルテを打撃・投手・守備・走塁・成長の5タブに拡張
- 直近傾向、OPS推移、長所・課題の自動抽出、育成方針と分類別メモ
- 対戦相手を打者、打順、投手左右、打球方向、バント、盗塁の観点から累計分析
- 要注意打者と試合前の戦術ポイントを含む印刷対応スカウティングレポート
- ダッシュボードに期間・試合種別・相手の絞り込みと条件クリアを追加

### 打席直後の進塁確認

安打・失策・野選で打者が出塁したとき、走者がいれば「🏃 走者はどこまで進んだ？」を表示します。1死2塁の単打を例にすると、自動進塁の1・3塁のほかに、2塁走者の生還(1得点で1死1塁)、送球間の打者走者の進塁(1死2塁)、本塁での憤死(2死1塁)をその場で選べます。

- 既定は自動進塁のまま。「記録する」を押すだけなら操作は1タップ増えるだけです
- 選んだ内容は既存の走者イベント記録(「2塁走者 打球で本塁へ」など)として保存されるため、速報・スコアブック・記録の再構築にそのまま反映されます
- 打球・送球間による生還は打者の打点と投手の自責点に数えます
- 確認を出すかどうかは、シート下部か「進塁」画面のチェックボックスで切り替えられます(`baseball_askAdvanceAfterHit_v1`)
- 進塁ルールは `src/runnerAdvance.js` に集約しています

### 自責点と防御率

回別スコア修正画面では、各回の「得点」と「自責点」を別々に入力できます。防御率は自責点を使った7回制の正式な式、自責点を区別しない失点率は `RA7` として別表示します。

旧データには自責点項目がないため、初回表示では得点と同じ値を自責点へ移行します。失策、捕逸、タイブレーク走者などによる非自責点がある試合は、保存／読込画面のスコア修正から訂正してください。自責点は得点を超えて入力できません。

## 控え選手への交代

オーダー設定の「＋ 控え追加」で登録した控え選手は、「🔄 交代」の**入る選手**欄にワンタップで選べる候補として並びます（控えの選手には「控」、すでに先発オーダーにいる選手には「出場中」を表示しますが、どちらも選択できます）。

- 控え選手が出場すると、オーダーに二重で並ばないよう控え欄からは自動的に外れます
- オーダー設定の「📋 登録選手から選択」で「出場中」となるのは、先発オーダー（打順9人＋控/投）に入っている選手だけです。控えに登録しただけの選手は交代要員なので、そのまま先発オーダーへ入れられます

## 選手交代の入れ忘れを試合後に修正する

交代を記録し忘れたまま試合が進んでしまった場合、あとからその場面まで遡って交代を挿入できます。挿入した交代より後の打席・投球記録は、自動で交代後の選手の記録に書き換わります。

1. 保存済みの試合は「📂 保存/読込」→ 該当試合の「🔄 記録/交代」で読み込みます(記録中の試合はそのまま「📝 記録修正」へ)
2. 記録の一覧から、交代を入れたい場面の右端にある「🔄 交代挿入」をタップします(その記録の**直前**に交代が入ります)
3. チーム・交代種別(代打/代走/守備/投手/位置変更)・対象の打順・入る選手を指定して「この場面に挿入」を押します
4. 保存済み試合を修正した場合は「📂 保存/読込」→「💾 読み込み元の試合へ上書き保存」で反映します

- 退く選手は、その場面の記録から復元した当時のオーダーで表示されます(交代後に打順が変わっていても、その時点の選手が対象になります)
- 書き換えの対象は「退いた選手の名前のまま残っている記録」だけです。あとの回で別の交代を記録済みの場合、その交代以降の記録は元のまま残ります
- 投手交代を挿入した場合は、その場面以降の相手打席の投手名・投球記録もまとめて新しい投手に付け替えます
- 挿入した交代がその打順の最新の交代であれば、現在のオーダーにも反映されます
- 挿入は「↩️ 戻る」(取り消し)で元に戻せます

### 守備位置だけの変更

選手は入れ替えず守備位置だけを動かす場合は、交代種別の「位置変更」を使います(試合中の交代・さかのぼり挿入のどちらでも使えます)。

- 入る選手の入力は不要で、選んだ打順の選手をそのまま別の守備位置へ動かします
- 移動先に他の選手がいる場合は、その選手が空いた守備位置へ玉突きで移動します(例: 左翼手→遊撃、遊撃手→左翼)
- 記録には `選手交代: [移]5番 山田 左→遊 (位置変更)` のように、退く/入るではなく「移動」として残ります
- その場面以降の記録の守備位置が書き換わります。玉突きでマウンドに入る選手がいる場合は、以降の相手打席の投手名・投球記録も付け替えます

## スコアブックPDF(画面 = 印刷)

スコアブックPDFは、別ウィンドウに開くプレビューがそのまま印刷結果になるよう、ブラウザの自動改ページに任せず紙面を自前で組みます(`src/scorebookReport.js`)。

- 1シート = A4横1ページ(287mm × 199mm)の固定枠。印刷側で寸法や段組みを組み替えないため、画面と印刷でレイアウトが変わりません
- 版面幅を広げて縮小する方式で倍率を自動決定します(単純な全体縮小より右端パネルの折り返しが減るので、少ない縮小でページ数を減らせます)。ページ数が最小になる中で最大の倍率を選びます
- 1ページに入らない場合は打者行の単位で改ページします。行の途中では切らず、試合ヘッダー・表ヘッダー・列幅は全ページ共通、フッターに `先攻スコア 1/2` のようにページ番号が入ります
- 個人成績はチームの1ページ目の右側に入ります。2ページ目以降も同じ列幅を保つため右側の枠は空けたままにします
- ページ数を減らしたいときは、出力設定で「配球図・打球方向図を載せる」を外すとコンパクトになります

## iOSアプリ

Capacitorで iOS アプリ化済みです(`ios/` ディレクトリ)。Macでのビルド手順は [docs/ios-build.md](docs/ios-build.md) を参照してください。

```bash
npm run ios:sync   # Webをビルドして iOS プロジェクトへ同期
npx cap open ios   # Xcodeで開く(Mac)
```

iOSアプリ版では localStorage に加えてネイティブストレージ(UserDefaults)へ二重保存し、起動時に自動復元します(`src/storage.js`)。

## デプロイ

`main` ブランチへの push で GitHub Actions がテスト・ビルドを実行し、GitHub Pages へ自動デプロイします(`.github/workflows/deploy.yml`)。
